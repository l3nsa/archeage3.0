## GM-команды

Все команды вводятся в игровой чат с префиксом `/`. Например: `/fly`, `/help spawn`.

### Команды для всех игроков (уровень доступа 0)

| Команда | Описание |
|---------|----------|
| `/help [команда]` | Показать справку по командам. Без аргумента — список всех доступных команд. С указанием команды — подробная справка по ней |
| `/fly` | Включить/выключить режим полёта для персонажа |
| `/online` | Показать количество игроков на сервере |
| `/soloparty` | Переключение режима соло/группа |
| `/teleport <название>` | Телепортация в указанную локацию |

### Команды модераторов (уровень доступа 50)

| Команда | Описание |
|---------|----------|
| `/announce <сообщение>` | Отправить объявление всем игрокам на сервере |
| `/despawn <id>` | Удалить указанный объект из мира (NPC, дудад и т.д.) |

## Система уровней доступа

Система уровней доступа определяет, какие команды доступны каждому игроку.

### Уровни доступа

| Уровень | Роль | Описание |
|---------|------|----------|
| **0** | Игрок | Базовые команды: `fly`, `help`, `online`, `soloparty`, `teleport` |
| **50** | Модератор | Команды управления игроками и спавна (16 команд) |
| **100** | Администратор | Полный доступ ко всем командам (47 команд) |

### Конфигурация (AccessLevels.json)

Файл `AccessLevels.json` находится в корневой директории Game-сервера. Формат — JSON с комментариями:

```json
{
    // Все игроки (уровень 0)
    "fly": 0,
    "help": 0,
    "online": 0,

    // Модераторы (уровень 50)
    "announce": 50,
    "spawn": 50,
    "kill": 50,

    // Администраторы (уровень 100)
    "additem": 100,
    "addgold": 100,
    "scripts": 100
}
```

### Изменение уровня доступа

1. Откройте файл `AccessLevels.json` в текстовом редакторе
2. Измените числовое значение напротив нужной команды
3. Выполните команду `/reloadconfig` в игре или перезапустите сервер
4. Уровень доступа игрока задаётся в базе данных `aaemu_login`, таблица `users`

> **Важно:** Команда `help` всегда должна оставаться на уровне 0, чтобы все игроки могли просматривать список доступных им команд.

## Управление конфигурацией

### Основные конфигурационные файлы

#### Config.json (Game-сервер)

Основной конфигурационный файл игрового сервера. Создаётся из `ExampleConfig.json`:

```json
{
    "Id": 1,
    "AdditionalesId": [],
    "SecretKey": "test",
    "AutoAccount": true,
    "Network": {
        "Host": "127.0.0.1",
        "Port": 1239,
        "NumConnections": 10
    },
    "StreamNetwork": {
        "Host": "127.0.0.1",
        "Port": 1250
    },
    "LoginNetwork": {
        "Host": "127.0.0.1",
        "Port": 1234
    },
    "Connections": {
        "MySQLProvider": {
            "Host": "localhost",
            "Port": "3306",
            "User": "root",
            "Password": "root",
            "Database": "aaemu_game"
        }
    },
    "CharacterNameRegex": "^[a-zA-Z0-9а-яА-Я]{1,18}$",
    "MaxConcurencyThreadPool": 8,
    "HeightMapsEnable": true
}
```

| Параметр | Описание |
|----------|----------|
| `Id` | Уникальный идентификатор игрового сервера |
| `SecretKey` | Секретный ключ для связи между Login- и Game-серверами. **Должен совпадать!** |
| `AutoAccount` | Автоматическое создание аккаунтов при первом входе (`true`/`false`) |
| `Network.Host` | IP-адрес для подключения клиентов |
| `Network.Port` | Порт игрового сервера (по умолчанию: `1239`) |
| `StreamNetwork.Port` | Порт потокового сервера (по умолчанию: `1250`) |
| `LoginNetwork.Host` | IP-адрес Login-сервера для внутреннего соединения |
| `LoginNetwork.Port` | Порт внутреннего соединения с Login-сервером (по умолчанию: `1234`) |
| `CharacterNameRegex` | Регулярное выражение для допустимых имён персонажей |
| `MaxConcurencyThreadPool` | Максимальное количество потоков в пуле |
| `HeightMapsEnable` | Включение карт высот (может замедлить первый запуск) |

#### Config.json (Login-сервер)

Конфигурация сервера авторизации. Создаётся из `ExampleConfig.json`:

```json
{
    "SecretKey": "test",
    "AutoAccount": true,
    "InternalNetwork": {
        "Host": "127.0.0.1",
        "Port": 1234
    },
    "Network": {
        "Host": "*",
        "Port": 1237,
        "NumConnections": 10
    },
    "Connections": {
        "MySQLProvider": {
            "Host": "localhost",
            "Port": "3306",
            "User": "root",
            "Password": "root",
            "Database": "aaemu_login"
        }
    }
}
```

| Параметр | Описание |
|----------|----------|
| `SecretKey` | Секретный ключ (должен совпадать с Game-сервером) |
| `AutoAccount` | Авто-создание аккаунтов |
| `InternalNetwork.Host` | IP для внутренней связи с Game-сервером |
| `InternalNetwork.Port` | Порт внутренней связи (по умолчанию: `1234`) |
| `Network.Host` | IP для подключения клиентов (`*` — все интерфейсы) |
| `Network.Port` | Порт для подключения клиентов (по умолчанию: `1237`) |

### Игровые данные (директория Data/)

| Файл | Описание |
|------|----------|
| `Configurations.json` | Основные игровые настройки (интервал автосохранения, множитель опыта) |
| `CharTemplates.json` | Шаблоны создания персонажей (стартовые характеристики, экипировка) |
| `worlds.json` | Определения игровых миров и зон |
| `housing_bindings.json` | Конфигурация привязок жилья |
| `expedition.json` | Данные гильдий и экспедиций |
| `slave_attach_points.json` | Точки крепления транспорта и маунтов |
| `npc_ai_params.xml` | Параметры поведения AI для NPC |
| `anim_durations.json` | Длительность анимаций |
| `compact.sqlite3` | Основная база данных игры (только чтение): предметы, умения, NPC, квесты и т.д. |

#### Configurations.json

```json
{
    "AutoSaveInterval": 1,
    "ExperienceMultiplierInPercent": "100"
}
```

| Параметр | Описание | Рекомендуемое значение |
|----------|----------|----------------------|
| `AutoSaveInterval` | Интервал автосохранения в минутах | `5`–`10` для продакшена, `1` для отладки |
| `ExperienceMultiplierInPercent` | Множитель получаемого опыта в процентах | `100` — стандартный, `200` — двойной опыт |

### Директория Data/Worlds/

Содержит данные 35+ игровых миров. Каждый мир имеет собственную директорию с файлами:

- `npc_spawns.json` — точки спавна NPC
- `zones.json` — определения зон
- `doodad_spawns.json` — точки спавна дудадов
- `transfer_spawns.json` — точки трансфера (только для основного мира)
- `npc_paths.json` — маршруты патрулирования NPC
- `gimmick_spawns.json` — спавн механик

Основной мир: `main_world/`

## Администрирование базы данных

Сервер использует MySQL для хранения данных. Существуют две основные базы данных.

### aaemu_login

База данных сервера авторизации:

| Таблица | Описание |
|---------|----------|
| `users` | Аккаунты игроков (имя, пароль, уровень доступа) |
| `game_servers` | Зарегистрированные игровые серверы |
| `user_sessions` | Активные сессии пользователей |

### aaemu_game

База данных игрового сервера:

| Таблица | Описание |
|---------|----------|
| `characters` | Данные персонажей (имя, уровень, позиция, характеристики) |
| `items` | Предметы в инвентарях и хранилищах |
| `skills` | Изученные умения персонажей |
| `quests` | Прогресс квестов |
| `housing` | Данные о жилье и участках |
| `mails` | Внутриигровая почта |
| `auction_house` | Лоты аукциона |
| `expeditions` | Гильдии и экспедиции |
| `family_members` | Члены семей |
| `friends` | Список друзей |
| `buffs` | Активные баффы персонажей |
| `actabilities` | Профессии и их прогресс |
| `appellations` | Титулы персонажей |

### Инициализация базы данных

SQL-скрипты для создания баз данных находятся в директории `SQL/`:

- `aaemu_login.sql` — создание базы данных `aaemu_login_3030` и необходимых таблиц
- `aaemu_game_full.sql` — создание базы данных `aaemu_game_3030` и всех игровых таблиц

```bash
mysql -u root -p < SQL/aaemu_login.sql
mysql -u root -p < SQL/aaemu_game_full.sql
```

### Автосохранение (SaveManager)

Система автосохранения работает через `SaveManager`:

- **Интервал сохранения:** задаётся в `Configurations.json` (параметр `AutoSaveInterval`, в минутах)
- **Сохраняемые данные:**
  - Жильё (`HousingManager`)
  - Почта (`MailManager`)
  - Предметы (`ItemManager`)
  - Аукцион (`AuctionManager`)
  - Персонажи (`CharacterManager`)
- **Транзакционность:** все данные сохраняются в рамках одной MySQL-транзакции
- **При ошибке:** транзакция откатывается, ошибка записывается в лог
- **При остановке сервера:** выполняется финальное сохранение всех данных

## Система логирования

Логирование реализовано через библиотеку NLog. Конфигурация находится в файлах `NLog.config` для каждого серверного модуля.

### Цели логирования

| Цель | Файл | Описание |
|------|------|----------|
| Консоль | — | Цветной вывод в реальном времени |
| Server.log | `Logs/Server.log` | Общий серверный лог (уровни Debug–Warn) |
| Error.log | `Logs/Error.log` | Только ошибки и исключения (уровни Error, Fatal) |

### Уровни логирования

| Уровень | Описание |
|---------|----------|
| `Debug` | Подробная отладочная информация |
| `Info` | Информационные сообщения (запуск модулей, подключения) |
| `Warn` | Предупреждения (нештатные ситуации, не критичные) |
| `Error` | Ошибки (сбои в обработке, ошибки базы данных) |
| `Fatal` | Критические ошибки (невозможность продолжить работу) |

### Формат лога

```
ЧЧ:ММ:СС [УРОВЕНЬ] ИмяЛоггера - Сообщение
```

Пример:
```
14:32:15 [INFO] GameServer - Server started on port 1239
14:32:15 [DEBUG] WorldManager - Loading main_world zones...
14:32:16 [ERROR] MySQL - Connection timeout
```

### Ротация логов

- **Server.log:** ежедневная ротация, хранение до 9 архивов
- **Error.log:** ежедневная ротация, хранение до 9 архивов
- Имя архива: `Server.{дата}.log`

### Фильтрация логов

- Логи планировщика Quartz фильтруются отдельно для уменьшения шума
- Можно настроить правила фильтрации в `NLog.config`, добавив дополнительные правила `<logger>`

## Мониторинг сервера

### Проверка состояния

| Метод | Команда / Действие |
|-------|-------------------|
| Онлайн-игроки | Команда `/online` в игре |
| Журнал сервера | Просмотр `Logs/Server.log` |
| Ошибки | Просмотр `Logs/Error.log` |
| Состояние MySQL | `mysql -u root -p -e "SHOW PROCESSLIST;"` |

### Сетевые порты

| Порт | Служба | Направление |
|------|--------|------------|
| **1237** | Login-сервер (клиенты) | Внешний — принимает подключения от игровых клиентов |
| **1239** | Game-сервер (клиенты) | Внешний — принимает подключения от игровых клиентов |
| **1250** | Stream-сервер | Внешний — потоковая передача данных |
| **1234** | Внутренняя связь Login↔Game | Внутренний — связь между серверами |
| **3306** | MySQL | Внутренний — база данных |

### Проверка доступности портов

```bash
# Проверка прослушивания портов
netstat -tlnp | grep -E '1237|1239|1250|1234'

# Проверка подключения к серверу
telnet 127.0.0.1 1237
telnet 127.0.0.1 1239
```

## Безопасность

### Критичные настройки

| Настройка | Рекомендация |
|-----------|-------------|
| `SecretKey` | Измените значение по умолчанию (`"test"`) на уникальный сложный ключ. **Должен совпадать** на Login- и Game-серверах |
| `AutoAccount` | Установите `false` в продакшене. При значении `true` любой может создать аккаунт при первом входе |
| MySQL пароль | Замените стандартный `root:root` на надёжный пароль |
| `CharacterNameRegex` | Настройте регулярное выражение для ограничения допустимых символов в именах |

### Настройка файрвола

```bash
# Разрешить только необходимые внешние порты
sudo ufw allow 1237/tcp   # Login-сервер (клиенты)
sudo ufw allow 1239/tcp   # Game-сервер (клиенты)

# Внутренние порты — только localhost
# Порт 1234 НЕ ДОЛЖЕН быть доступен из внешней сети
# Порт 3306 (MySQL) НЕ ДОЛЖЕН быть доступен из внешней сети
```

### Рекомендации по безопасности

1. **Никогда** не оставляйте `SecretKey` со значением `"test"` на публичном сервере
2. **Отключите** `AutoAccount` на продакшен-серверах
3. **Ограничьте** доступ к порту `1234` (внутренняя связь) только с `localhost`
4. **Используйте** отдельного пользователя MySQL с минимальными правами (не `root`)
5. **Регулярно** проверяйте `Error.log` на предмет подозрительной активности
6. **Назначайте** уровни доступа в базе данных только проверенным пользователям

## Резервное копирование и обслуживание

### Резервное копирование базы данных

```bash
# Полный дамп базы данных авторизации
mysqldump -u root -p aaemu_login > backup_login_$(date +%Y%m%d).sql

# Полный дамп игровой базы данных
mysqldump -u root -p aaemu_game > backup_game_$(date +%Y%m%d).sql
```

**Рекомендуемое расписание:**
- Ежедневно: полный дамп обеих баз данных
- Перед обновлениями: обязательный бэкап

### Что нужно/не нужно бэкапить

| Компонент | Необходимость бэкапа | Причина |
|-----------|---------------------|---------|
| MySQL базы данных | ✅ Обязательно | Данные игроков, персонажей, предметов |
| Config.json (Login и Game) | ✅ Обязательно | Настройки сервера |
| AccessLevels.json | ✅ Обязательно | Права доступа к командам |
| Data/Configurations.json | ✅ Обязательно | Игровые настройки |
| Data/Worlds/ | ✅ Рекомендуется | Кастомные спавны NPC и дудадов |
| compact.sqlite3 | ❌ Не требуется | Файл только для чтения, входит в дистрибутив |
| Logs/ | ❌ Не требуется | Автоматическая ротация (9 дней хранения) |

### Обслуживание

- **Ротация логов:** автоматическая, хранение до 9 архивов
- **Оптимизация MySQL:** периодически выполняйте `OPTIMIZE TABLE` для крупных таблиц
- **Конфигурационные файлы:** рекомендуется хранить в системе контроля версий (Git)
- **Обновление сервера:** остановите сервер → сделайте бэкап → обновите файлы → запустите сервер

### Перезапуск сервера

1. Дождитесь завершения текущего цикла автосохранения (проверьте в логах)
2. Остановите Game-сервер (Ctrl+C или закрытие окна)
3. Остановите Login-сервер
4. Убедитесь, что процессы завершены
5. Запустите Login-сервер
6. Дождитесь полной инициализации
7. Запустите Game-сервер

> **Примечание:** при корректном завершении работы `SaveManager` автоматически выполняет финальное сохранение всех данных.
